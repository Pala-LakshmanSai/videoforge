# VF-1-04 — private artifact storage adapter

Status: standing provider-free authority after VF-1-02

## Goal and dependencies

Implement the artifact-store port with a local R2-compatible adapter, signed multipart lifecycle,
content checksums, workspace prefixes, expiry, retention, and access controls. VF-1-02 must be
green; real R2 waits for staging authority.

Read profile: `phase1_artifacts`.

## Scope and ownership

- Own artifact adapter/domain modules and isolated artifact tests only.
- Separate binary and canonical-document hashes, validate multipart completion, and never proxy
  large bodies through the Worker application.
- Use short-lived path-scoped local signatures; deny cross-workspace probes and traversal.
- Preserve local-filesystem media slice behavior through the same port.
- Integration owner alone edits dependencies, app composition, shared schemas, migrations, root
  scripts, context, or commits.
- Out of scope: R2 account/bucket mutation, production credentials, browser redesign, providers,
  public URLs, and spend.

## Acceptance

- Initiate/part/complete/abort/download/expiry/retry are deterministic and idempotent.
- Checksum, size, content type, workspace, project/revision and retention mismatches fail closed.
- Large-upload tests prove bytes bypass application bodies.
- Owned lint/typecheck/tests pass; integration runs full uncached verify, local-slice regression,
  Chrome upload coverage, secret scan, dependency audit, and diff check.
