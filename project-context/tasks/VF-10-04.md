# VF-10-04 — V2-04 Serverless v3 contracts

Status: blocked on accepted V2-03; provider-free

## Goal

Define and implement the provider-neutral Serverless authority, transport, transactional outbox,
dispatch-token, signed provenance-receipt, cost-reservation, and recovery contracts.

## Scope

- Bind tenant/revision/lane/endpoint/config/image/model/volume/deadline/cost before dispatch.
- Accept at most one output per dispatch token; expose and reconcile duplicate-compute risk because
  RunPod does not promise client idempotency or exactly-once billing.
- Fake `/run`, `/status`, `/cancel`, webhook loss, unknown acknowledgement, duplicate delivery,
  timeout, TTL expiry, worker death, and result expiry. Never use `/purge-queue`.
- Pin measured-timeout fields and the exact receipt/hash parity in TypeScript and Python.
- Generalize context validation from historical CP-06-only authority rules to exact V2 external
  checkpoint profiles without weakening operation/resource/rate/cap checks.

No credentials, provider calls, endpoint/image mutation, GPU work, or spend belongs here.
