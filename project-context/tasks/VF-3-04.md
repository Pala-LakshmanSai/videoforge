# VF-3-04 — RunPod API lifecycle account preflight

Status: exact account/API preflight task

## Goal and dependencies

Establish secure API-only RunPod lifecycle access, inventory all billable compute, and leave every
Pod stopped and every Serverless endpoint at zero active workers. Depends on green VF-3-03 and the
user's 2026-08-10 credential/account authority. This is not model or GPU qualification and cannot
close `GATE_RUNPOD_001`.

Read profile: `phase3_runpod_account_preflight`.

## Scope and ownership

- Create one named RunPod API key with lifecycle-capable access and store it directly in macOS
  Keychain without displaying, logging, or committing its value.
- Query the authenticated RunPod API for account identity/balance, Pods, Serverless endpoints, and
  other active billable compute needed to prove the account starts drained.
- If a pre-existing Pod is running, stop it. If a pre-existing Serverless endpoint can run workers,
  set its maximum workers to zero. Do not delete user resources.
- Record only redacted counts, states, balance, checked time, API surfaces, and credential location.
- Preserve the non-transferable RunPod lifecycle/fallback cap of `$5`; spend in this preflight is
  exactly `$0`.

## Out of scope

- Pod/endpoint/template/volume creation, model downloads, provider inference, SSH/Jupyter work,
  image/avatar generation, application code, remote/cloud staging, production, or resource deletion.
- No attempt to qualify Mage, AvatarForcing, SkyReels, GPU compatibility, cost, dispatch ambiguity,
  callbacks, or output lifecycle.

## Acceptance

- A lifecycle-capable key exists only in Keychain; secret scan and repository search reveal no value.
- Authenticated API reads succeed and record redacted inventory evidence.
- Running Pods equal zero at handoff; Serverless active workers equal zero and every existing
  endpoint has `workersMax=0` or an equivalent disabled state.
- Balance does not decrease and task spend is `$0`.
- `pnpm context:validate`, `pnpm secret:scan`, `git diff --check`, and a clean handoff pass.
- Evidence: `evidence/acceptance/VF-3-04/runpod-account-preflight`.

## Safety, rollback, handoff

- `provider_calls_authorized: false`; maximum external spend `$0`; no model/provider call.
- A Pod stop or endpoint scale-to-zero is an authorized reversible safety action. No deletion.
- Stop on MFA/CAPTCHA, API identity ambiguity, unknown billable resource type, failed drain, secret
  exposure, unexpected charge, or any request to create compute.
- On pass, author/select only the next dependency-ready provider-free or staging brief. A later exact
  brief is required before any Pod, endpoint, GPU, model, inference, or spend activation.
