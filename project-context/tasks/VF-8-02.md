# VF-8-02 — Locked Runware runtime composition

Status: exact successor selected after VF-8-01

## Goal

Compose the already qualified DeepSeek V4 Flash prompt writer and Gemini 3.5 Flash style analyzer
behind the durable sandbox authority without changing either locked role or fixture defaults.

## Context read profile

Use `phase8_runware_runtime` from `MANIFEST.yaml`.

## In scope

- Add one server-only Runware HTTP transport and explicit sandbox configuration.
- Compose `deepseek:v4@flash` for batched image prompts and `google:gemini@3.5-flash` only for an
  explicitly requested new-style analysis.
- Bind immutable request/input/profile hashes, idempotency, timeout, bounded retry, provider usage,
  reported cost, and redacted failure evidence to existing durable services.
- Add fake-transport tests for malformed responses, timeout, replay, cap exhaustion, and secret
  redaction; perform only the smallest live smoke needed to prove runtime wiring.

## Authority and limits

- Credential access is limited to the existing macOS Keychain Runware entry; never print, copy to
  Git, expose to browser code, or persist the value.
- Provider calls authorized: Runware only, exact locked models above.
- Maximum new external spend: `$0.20`; stop before the cap.
- No RunPod/GPU/cloud resource, model download, deployment, push, model-role change, or UI redesign.

## Acceptance

- Fixture/local remain `$0`; sandbox rejects live composition without explicit credential and cap.
- Fake transport covers all failure/replay/redaction boundaries.
- One bounded live DeepSeek smoke and, only if needed for composition proof, one tiny owned/synthetic
  Gemini smoke return exact validated contracts with usage/cost.
- Focused tests, `pnpm verify:fast`, context/schema validation, secret scan, dependency audit,
  Prettier, and `git diff --check` pass; server stopped at handoff.
- Evidence: `evidence/acceptance/VF-8-02/runware-runtime`.
