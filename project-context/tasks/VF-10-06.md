## Superseding personal-worker decision — 2026-08-17

- The user selected free local CPU compute. `DEC_PERSONAL_WORKER_001` supersedes the Cloud Run
  production clauses of `DEC_TIMING_001`, `DEC_RENDER_001`, and `DEC_HOSTING_001` and the former
  blanket production-device-independence clause of `DEC_BUILD_001`.
- The app offers the detected OS first and always exposes both Windows and Mac downloads. After a
  normal installer launch, the user confirms `Connect this computer` once in the signed-in browser.
  There is no provider credential, database URL, R2 key, copied pairing code, port, model, or path
  configuration.
- The background worker starts at login, uses outbound HTTPS only, and may claim only the paired
  account's work. Offline truth is `Waiting for your computer`; another tenant's device is never a
  fallback.
- Successful final videos are not deleted automatically. Only an explicit authenticated user Delete
  removes the durable R2 object. Job scratch is removed on completion, cancellation, or failure.
- CPU provider spend is `$0`, but the product must still report user electricity/device time, R2,
  Runware, and RunPod costs separately. Signed/notarized installer publication and live acceptance
  remain external gates and are not authorized by local implementation work.
