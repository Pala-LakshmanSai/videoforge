# VF-8-07 — AvatarForcing inference failure observability

Status: exact successor selected after VF-8-06 bounded inference failure

## Goal

Replace generic `AVATAR_PRIMARY_FAILED` with deterministic, secret-safe inference failure evidence,
publish a pinned worker image, and keep RunPod at zero.

## Context read profile

Use `phase8_avatarforcing_failure_observability` from `MANIFEST.yaml`.

## In scope

- Capture bounded subprocess output and classify timeout, CUDA OOM, missing asset, missing module,
  invalid media, and other process failures into stable codes.
- Return only a stable code plus SHA-256 of redacted diagnostic bytes; never return raw paths,
  provider environment, credentials, or unrestricted logs.
- Retain the failure code/hash in the local qualification evidence envelope.
- Add focused Python/TypeScript tests and GHCR built-container smoke, then publish by digest.

## Authority and limits

- `$0` external spend; no RunPod credential read, mutation, dispatch, model download, or GPU start.
- No model substitution, provider promotion, MuseTalk/SkyReels/Mage execution, UI/schema redesign, or
  deployment.
- RunPod inventory must remain absolute zero.

## Acceptance

- Every recognized subprocess failure maps deterministically; raw diagnostic text never crosses the
  worker boundary.
- A failed provider envelope persists safe code/hash instead of collapsing to
  `AVATAR_PRIMARY_FAILED`.
- Pinned GHCR image passes dependencies, source compile, and handler-registration smoke.
- Focused verification, context/schema/secret/diff checks pass; server stopped and RunPod zero.
