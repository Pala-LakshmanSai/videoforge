# VF-3-07 — Runware DeepSeek prompt-writer adapter

Status: exact provider-free application-adapter task

## Goal and dependencies

Implement the production-shaped Runware DeepSeek prompt-writer adapter behind injected ports while
normal application/provider mode remains `fixture`. Depends on closed `GATE_LLM_001`, green
VF-3-03 prompt batching/compiler, and the committed provider-sandbox safety patterns. This task
does not authorize a live provider call.

Read profile: `phase3_runware_prompt_adapter`.

## Scope and ownership

- Own only `packages/pipeline/src/prompts/**`, its tests/exports, task evidence, and handoff context.
  The integration owner alone edits shared package metadata, root scripts, lockfiles, and context.
- Add a Runware prompt-writer adapter with an injected transport and injected attempt-evidence sink;
  no ambient environment, credential lookup, global `fetch`, SDK singleton, filesystem, or clock.
- Pin canonical AIR `deepseek:v4@flash`, `scene-prompt-writer-v1`, the exact strict response schema,
  deterministic request bytes/hash, and the committed 25–50-scene batch input.
- Treat every provider response as untrusted. Preserve exact batch/scene identity, code-assigned shot
  roles, literal narration anchors, continuity tags, and all existing forbidden-output rules through
  `validatePromptWriterOutput` before compilation.
- On a partially malformed first response, retain only independently valid expected scene rows and
  make at most one bounded retry containing only missing/invalid expected scenes. Merge in original
  order and revalidate the complete original batch. Unknown/duplicate IDs, changed roles, bad
  anchors, malformed top-level output, ambiguous transport outcome, or invalid cost/usage evidence
  must fail closed without silently accepting partial production state.
- Expose redacted per-attempt evidence needed by later durable orchestration: canonical model,
  request/response hashes, requested scene IDs, retry lineage, latency, provider usage/cost, finish
  reason, and validation disposition. Never expose prompts or credentials through logs.

## Out of scope

- Live Runware calls, credential access, external spend, application route/runtime composition,

  grammar. The deterministic fixture writer remains the default.

## Acceptance

- Fake-transport tests cover exact 25- and 50-scene batches, five style profiles, deterministic
  request/hash replay, 100% first-pass success, one-scene and multi-scene partial recovery, retry
  exhaustion, malformed JSON/schema, unknown/duplicate/missing IDs, changed roles, missing literal
  anchors, forbidden output, usage/cost drift, transport ambiguity, timeout, and reordered output.
- A partial retry sends only unresolved expected scenes, never rewrites accepted first-attempt rows,
  and the final merged result is byte-equivalent for identical inputs/evidence.
- Import/build/test paths perform zero network, credential, provider, or filesystem activity.
- Targeted pipeline tests, then `TURBO_FORCE=true pnpm verify`, context validation, secret scan, and
  diff check pass at `$0`. Evidence:
  `evidence/acceptance/VF-3-07/runware-deepseek-prompt-adapter`.
