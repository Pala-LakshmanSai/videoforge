# VF-10-11 — V2-11 live autoscaling, fairness, and essential recovery

Status: blocked on accepted V2-10; external activation checkpoint; 3–4-hour best-case timebox

## Goal

Prove two different accounts can generate concurrently, a same-account second job and extra
accounts wait durably/fairly, and both Mage/SoulX endpoints autoscale back to zero.

## Scope

- Reuse accepted provider-free 10-account admission proof; rerun one contention test only if queue
  code changed.
- Promote exact lane configs to max2 only after max1 acceptance; keep `REQUEST_COUNT=1`, handler
  concurrency 1, RTX 4090, and Postgres fairness.
- For each exact lane, deliberately exercise two simultaneous read-only workers against the same
  sealed volume and prove unchanged pre/post manifests plus exact max1/max2 config readback/restore.
- Run two short owned projects from different accounts, show same-account and third-account waiters,
  then fair promotion and private status.
- Exercise one real essential failure/recovery path plus cancel/reconciliation.
- Do not run the exhaustive historical fault matrix.

## Minimum proof

At most one workload/account, two accounts/four GPU workers globally, tenant-private state/artifacts/
costs, durable receipts, duplicate-cost visibility, valid results, two simultaneous readers per
lane, unchanged volume manifests, exact config restoration, terminal jobs, zero endpoint jobs,
endpoints `0 -> demand -> 0`, zero workers, and one independent audit.
