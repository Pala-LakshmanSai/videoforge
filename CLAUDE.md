# VideoForge project context

Read `project-context/00_START_HERE.md`, `project-context/MANIFEST.yaml`, and `project-context/CURRENT_STATE.yaml` first, then use one task-specific read profile.

The folder `project-context/` is the source of truth for product, output grammar, models, architecture, costs, UI/UX, development sequence, tests, source evidence, and unresolved validation gates. Follow the manifest's precedence and reconcile any mismatch rather than choosing silently.

Do not infer permission to implement from these plans. Do not introduce motion graphics, captions, overlays, decorative transitions, AI-selected timeline layout, paid transcription, always-on GPU workers, per-video/per-image style-analysis calls, or per-project avatar uploads. Projects select and pin an exact ready Avatar Profile version/runtime source/compatibility preflight snapshot plus the style version/hash and extra-keyword text/toggle; the default image style is `documentary_stock_v1`. If a user-approved decision changes, update and validate the context pack according to `project-context/16_CONTEXT_MAINTENANCE.md` in the same task.
